# Приложения для Android и Mac

Оба приложения — окно с веб-версией с `https://notes.e40in.ru/`. Своего
интерфейса у них нет: страница приходит с сервера, без сети её отдаёт
service worker из кеша, данные лежат в IndexedDB самого приложения и
синхронизируются как в браузере. Поэтому интерфейс обновляется выкаткой веба,
а APK и DMG пересобирать нужно, только когда меняется сама оболочка.

Клиентский сертификат приложения берут из системы и отдают только своему серверу.

| | Android | Mac (Apple Silicon) |
|---|---|---|
| Код | `android/` — одна Activity с WebView, Java | `desktop/` — Electron |
| Сертификат | системное хранилище (KeyChain) | Связка ключей |
| Сборка | `scripts/build-android.sh` | `scripts/build-mac.sh` |
| Результат | `dist-native/android/microdocs-<версия>.apk` | `dist-native/mac/microdocs-<версия>-arm64.dmg` |

## Установка

### Android

1. Сертификат: скопировать `client.p12` на телефон, затем «Настройки →
   Безопасность → Шифрование и учётные данные → Установка сертификатов →
   Сертификат пользователя VPN и приложений» (пункты немного отличаются
   у разных производителей). Пароль — тот, с которым выпускали p12.
2. APK: скачать со страницы релиза на GitHub и открыть; телефон попросит
   разрешить установку из этого источника.
3. При первом запуске Android спросит, какой сертификат дать приложению, —
   выбрать свой. Выбор запоминается.

Первый запуск нужен с интернетом: после него приложение открывается и без сети.

### Mac

1. Сертификат: `client.p12` двойным щелчком, в связку «Вход». Если браузер
   уже ходит на notes.e40in.ru, сертификат там уже есть.
2. DMG: открыть, перетащить microdocs в «Программы».
3. Подписи Apple нет (только ad-hoc), поэтому скачанное из интернета macOS
   откроет только после снятия карантина — один раз:
   ```bash
   xattr -dr com.apple.quarantine /Applications/microdocs.app
   ```
   Собранное на своём маке открывается сразу.
4. При первом входе macOS спросит доступ к ключу сертификата — «Разрешать
   всегда». После каждой новой сборки приложения вопрос повторится: подпись
   ad-hoc у каждой сборки своя.

## Сборка

### Android — `scripts/build-android.sh`

Нужны JDK 17+ и Android SDK. На маке:

```bash
brew install --cask temurin android-commandlinetools
```

Недостающие части SDK (platform 35, build-tools) скрипт доставит сам.

```bash
scripts/build-android.sh              # подписать своим ключом
scripts/build-android.sh --debug-key  # без своего ключа — только для проверки
```

APK встаёт поверх старого, только если подписан тем же ключом, поэтому ключ
создаётся один раз и хранится вне репозитория:

```bash
scripts/android-keystore.sh
```

Ему тоже нужен JDK (`keytool`). Скрипт кладёт ключ в `.secrets/android/`. Если стоит `gh` с входом в GitHub,
он сам записывает секреты `ANDROID_KEYSTORE_BASE64` и `ANDROID_KEYSTORE_PASSWORD`
для сборки релизов; иначе печатает, что вставить в Settings → Secrets and
variables → Actions. **Ключ нужно сохранить**: без него обновление не
выпустить — только удалить приложение и поставить заново.

Номер сборки (versionCode) — число коммитов в истории: растёт сам.

### Mac — `scripts/build-mac.sh`

Нужны macOS и Node 22. Скрипт ставит зависимости `desktop/` и собирает DMG
для arm64 с подписью ad-hoc.

### Переменные обоих скриптов

- `MICRODOCS_VERSION` — версия (по умолчанию 0.1.0);
- `MICRODOCS_URL` — адрес сервера, если не notes.e40in.ru.

## Релиз

```bash
git tag v0.2.0
git push origin v0.2.0
```

`.github/workflows/apps.yml` собирает APK на Ubuntu и DMG на macOS теми же
скриптами и публикует оба файла в GitHub Releases. Без секретов с ключом
Android релиз не соберётся — с понятной ошибкой.

Пуши в ветки, где менялись `android/`, `desktop/` или скрипты сборки, тоже
собираются — для проверки: APK там подписан отладочным ключом, файлы лежат
в артефактах запуска. Для Mac CI дополнительно проверяет подпись и что
приложение запускается.

## Как устроено

- **Офлайн** — `src/serviceWorker/`: при установке кладёт в кеш всю сборку
  (index.html, JS, CSS, шрифты, emojibase), при показе — вложения. Переход
  по любому адресу приложения отдаёт index.html из кеша, API идёт мимо.
- **Обновление** — новая версия ставится в фоне; рядом со статусом
  синхронизации появляется «Обновить» (`src/state/useAppUpdate.ts`).
  Приложение проверяет обновления, когда к нему возвращаются.
- **Ошибки** — если открыть нечего (первый запуск без сети, нет сертификата),
  приложение показывает, что случилось, и кнопку «Повторить».
- **Mac** — окно помнит размер и место; закрытое окно оставляет приложение
  в доке, как принято на маке.
- **Android** — «Назад» листает историю страниц; при повороте страница
  не перезагружается.

## Ограничения

- На Android вложения, которые не картинки (PDF и прочее), не открываются:
  WebView не умеет сам, а системный загрузчик не знает о сертификате.
- targetSdk 34, не 35: с 35 Android 15 рисует окно под системными полосами
  и отступы пришлось бы расставлять вручную. Для установки не из Google Play
  это ни на что не влияет.
- Цвет системных полос на Android следует теме системы, а не переключателю
  темы в приложении.
