# Ход работы над MVP

Ветка `mvp`. Требования — в [REQUIREMENTS.md](REQUIREMENTS.md).
После каждого шага: критика решения и кода, реальная проверка (юниты или браузер), коммит.

## Шаги

- [x] **0. Бакет и версионирование.** `microdocs-data` в проекте MWS `microdocs`,
      versioning Enabled, публичной политики нет.
- [x] **1. Скелет.** Vite + React + TS + Mantine 9, запускается, тёмная/светлая тема.
- [x] **2. Модель данных.** Структура в `Tree`, тела отдельно, операции над деревом
      (перенос, запрет цикла), `PageStore` за интерфейсом, реализация на IndexedDB, юниты.
- [x] **3. UI дерева.** Создание, переименование через шапку страницы, вложение,
      перенос через меню и окно выбора родителя, удаление с подтверждением.
      Без drag-and-drop.
- [x] **4. Редактор.** TipTap 3 + `tiptap-markdown`, разметка по ходу набора (FR-20),
      автосохранение с задержкой. Проверено в браузере: `## ` и `- ` превращаются
      в заголовок и список, в хранилище лежит Markdown, правка переживает
      переключение страницы.
- [x] **5. Синк с S3.** Обработчик API поверх S3 (ключ только на сервере),
      локальное хранилище остаётся основным, неотправленное копится в очереди
      и уезжает при возврате связи. Проверено в браузере целиком: правка доезжает
      до бакета, обрыв сети переводит статус в «нет связи» и не мешает править,
      после возврата связи очередь пустеет и текст оказывается в S3.

## Раскладка в S3

```
<baseId>/tree.json        — структура: порядок, вложенность, заголовки
<baseId>/pages/<id>.md    — тело страницы, Markdown
```

История версий — версионирование объектов S3 (NFR-7), своего механизма нет.

## Проверка

Логика и поведение UI покрыты тестами (`npm test`): операции над деревом, меню строки,
окно переноса, сценарий переноса целиком.

Автоматизация браузера для меню Mantine в этом окружении ненадёжна: скриншот не захватывает
наложения из портала, а открытое меню «залипает» между действиями и перехватывает клики,
адресованные другой строке. Это свойство инструмента, не приложения — поэтому поведение UI
проверяется юнит-тестами, а браузер использую для внешнего вида.

## Решения и ограничения MVP

- Интерфейс русский, тема плотная, светлая и тёмная по системной настройке.
- Типографика страницы — вариант «Плотный» (`src/document.css`), увеличенный на ступень:
  Inter 16/1.55, заголовки 22 · 18 · 16 при названии 28, колонка 640px. Inter лежит в сборке (`@fontsource-variable/inter`),
  чтобы офлайн не подменялся системным шрифтом. Стенд с отвергнутыми вариантами —
  `design/typography-lab.html`.
- Удаление мягкое, интерфейса корзины нет.
- **FR-22 (побайтовая стабильность round-trip) в MVP не выполняется** — `tiptap-markdown`
  нормализует разметку. Смягчено тем, что запись происходит только по реальной правке:
  открыть и закрыть страницу её не переписывает. Если нормализация будет мешать —
  кандидат на замену Milkdown.
- **Чек-листы (`- [ ] `) не поддержаны:** их нет в StarterKit, нужны два отдельных
  расширения. FR-3 их требует, в MVP сознательно опущены.
- Вне MVP: авторизация, публичность баз, поиск, история в UI, картинки.
- Перетаскивание страниц по дереву — нативный drag-and-drop браузера, только мышью.
  На телефоне страницы переносятся через меню строки.

## Чего нельзя выкатывать наружу как есть

**У API нет никакой авторизации.** Dev-сервер поднимается с `--host`, то есть слушает
всю локальную сеть: любой в той же сети может читать и писать бакет через `/api/...`.
Для работы на своей машине это терпимо, для чего-либо ещё — нет. FR-40 (правка только
по владельческому секрету) не выполнен: делать половину авторизации хуже, чем не делать
вовсе, поэтому она отложена до шага с выкаткой.

Что уже сделано правильно: ключ к S3 живёт только на сервере и в браузер не попадает
(NFR-17), бакет закрыт от публичного доступа, идентификаторы проверяются регулярным
выражением перед подстановкой в ключ объекта — обход пути через `../` невозможен.
